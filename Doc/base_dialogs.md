# Базовые диалоги

## Диалог 1. Подбор ролей по АС с неофициальным названием

### Сценарий

Пользователь: Какая мне необходима роль в АС ЕФС?

Ожидаемый ответ агента:

> Добрый день. Я помогу вам с ответом. Для начала уточните, какая у вас должность?

Пользователь: риск-менеджер

Ожидаемый ответ агента:

> Уточните, пожалуйста, ваш город по штатной структуре.

Пользователь: Москва

Ожидаемый ответ агента:

> Уточните, пожалуйста, ваш отдел или подразделение по штатной структуре.

Пользователь: Отд КК НСК_Риск-менеджер

Ожидаемый ответ агента:

> Я нашел несколько АС, в названии которых есть `ЕФС`. Вот первые 5 вариантов:
>
> 1. `АС ЕФС. Наш бизнес (И2) [CI02040474]`
> 2. `ЕФС База знаний SberHelp (ПРОМ) (И3) [CI06055442]`
> 3. `ЕФС ЕРМ ЦКР (И2) [CI01982477]`
> 4. `ЕФС - Сотрудники. Кредитная машина (ПРОМ) (И3) [CI02637239]`
> 5. `ЕФС.Сотрудники.Риск-решения (ПРОМ) (И2) [CI04206161]`
>
> Укажите номер подходящей АС или напишите `показать еще`.

Пользователь: Тут нет необходимой АС

Ожидаемый ответ агента:

> Покажу следующие варианты АС, где в названии есть `ЕФС`.

Пользователь: Ок

Ожидаемый ответ агента:

> Других АС, где в официальном названии есть `ЕФС`, в текущем справочнике нет.
>
> Если нужной системы нет в этом списке, напишите:
>
> 1. как ее обычно называют в работе
> 2. для чего она нужна
> 3. какие слова или сокращения помните
>
> По этому описанию я попробую подобрать нужную АС по смыслу.

Пользователь: ЕФС ЕРМ ЦКР (И2) [CI01982477]

Ожидаемый ответ агента:

> Для вас, на основании должности / города / отдела для АС `ЕФС ЕРМ ЦКР (И2) [CI01982477]` доступны следующие роли:

Пользователь: Возможно я ошибся. Посмотри SberHelp

Ожидаемый ответ агента:

> Для вас, на основании должности `риск-менеджер`, города `Москва` и отдела `Отд КК НСК_Риск-менеджер`, для АС `ЕФС База знаний SberHelp (ПРОМ) (И3) [CI06055442]` доступна следующая роль:
>
> 1. `ЕРМ.ЦКР SberHelp Читатель SberHelp`
>    тип: `Полномочия`
>    доступ: `по умолчанию`

### Примечания к реализации

1. Агент должен сначала собрать должность, город и отдел, а уже потом предлагать варианты АС.
2. Если пользователь указывает только широкое название, например `ЕФС`, агент должен показывать первую страницу подходящих АС.
3. Если подходящих АС больше нет, агент должен явно сообщать об этом и просить дополнительные ориентиры.
4. После выбора АС агент должен выдать роли для найденного профиля в этой АС.
5. Если пользователь меняет направление поиска, например просит `Посмотри SberHelp`, агент должен сохранить уже собранный контекст и продолжить с новой АС.

## Диалог 2. Проверка конкретной роли в выбранной АС

### Сценарий

Пользователь: Как мне получить роль `ЕРМ.ЦКР SberHelp Читатель SberHelp` в `ЕФС База знаний SberHelp`?

Ожидаемый ответ агента:

> Для начала уточните должность, город и отдел по штатной структуре.

Пользователь: риск-менеджер

Пользователь: Москва

Пользователь: Отдел Фрод экспертизы

Ожидаемый ответ агента:

> Для найденного профиля роль `ЕРМ.ЦКР SberHelp Читатель SberHelp`:
>
> - либо `по умолчанию`;
> - либо `по запросу`.

Если роль `по умолчанию`:

> Агент сообщает, что доступ должен быть выдан автоматически, и дает рекомендации по проверке/эскалации.

Если роль `по запросу`:

> Агент дает шаги, как оформить запрос, и прикладывает ссылки на источники (слайды).

### Примечания к реализации

1. Агент не должен отвечать до сбора `должность + город + отдел`.
2. Ответ должен явно содержать статус роли: `по умолчанию` или `по запросу`.
3. Для инструкций агент должен использовать grounded источник и приводить citations.

## Диалог 4. Чистый инструкционный вопрос без АС

### Сценарий

Пользователь: Как проверить доступные АС и применить ролевую модель?

Ожидаемый ответ агента:

> Агент сразу отвечает шагами по инструкции, без обязательного уточнения АС.
>
> Ответ должен содержать citations на слайды.

Пользователь: Что делать, если роли не применились?

Ожидаемый ответ агента:

> Агент выдает troubleshooting шаги из памятки:
>
> - не совмещать ролевую модель и заявки через `ДРУГ`;
> - проверить, что это не технический сбой;
> - при необходимости обратиться в поддержку.

### Примечания к реализации

1. Это `INSTRUCTION_LOOKUP` path.
2. Для текущей памятки допускается `INLINE_DOC`, но ответ должен оставаться grounded.
3. Для procedural-ответов нужны citations.

## Диалог 5. Переключение контекста в середине подтверждения

### Сценарий

Пользователь: Какие роли доступны в ЕФС?

Пользователь: риск-менеджер

Пользователь: Москва

Пользователь: Отдел Фрод экспертизы

Агент показывает варианты АС/профиля.

Пользователь: Нет, давай другую систему — `ЕФС.Сотрудники.Риск-решения`.

Ожидаемый ответ агента:

> Агент не теряет уже собранные `должность/город/отдел`.
>
> Агент сбрасывает только system/profile-зависимый контекст и пересчитывает результат для новой АС.

Пользователь: А как запросить доступ, если роли нет?

Ожидаемый ответ агента:

> Агент совмещает structured + instruction:
>
> - сначала сообщает факт доступности роли (если найдена);
> - затем дает шаги из инструкции (если нужен процесс получения/эскалации).

### Примечания к реализации

1. Сообщения о смене АС должны обрабатываться как interrupt в любом состоянии.
2. Реплики типа `Ок`, `еще`, `дальше` в browse-фазе должны листать кандидатов, а не ломать поток.
3. Нельзя зацикливаться на «не удалось распознать подтверждение».
